## Stage C3: Up / Down over any value; MASTER FX knobs follow the same rules

Reported on the Mac: the MASTER FX sliders did not behave like the rest of the program, and a value could not be nudged with the keys by pointing at it.

- **The mouse over a value + Up / Down = one step** (like a wheel notch; Shift = finer), for every `ValueField` (BPM, LEN, SWING, faders, mixer EQ, CHORD LAB SOUND...) and every MASTER FX knob. The control under the mouse takes the arrows for the frame (`interaction::NoteValueHover` / `ClaimArrowsForHoveredValue` / `ArrowSteps`, called at the top of `DrawShellFrame`), so the grid, the piano roll and the instrument block do not move at the same time. Not with Option (PITCH) or Cmd, not while typing.
- **Instrument block:** the cell under the mouse becomes the selected one (`ParamCellResult::hoverStarted`), so Up / Down change the cell you point at; Left / Right still move the selection.
- **MASTER FX knobs are `ValueField`s** in a new box look (`ValueSpec::box`, `BoxSpec`): drag moves from where the knob is, Shift finer, Option+click = the default (`FxSettings{}` / `MasterChainSettings{}`), wheel, double-click types the number in the unit shown under the knob. Before, `KnobAbsolute` had its own drag with none of these.
- **Fix:** the value bubble over a percent knob said "DELAY TONE 1%" for 70 % (a 0..1 value printed as percent); it now scales like the text under the knob.
- Removed the unused `KnobRelative`.
- 5 new `t8_selftest` checks (source ratchets): the hovered value takes the arrows before anything reads them; a MASTER FX knob is a ValueField; every MASTER FX knob has a default; the instrument cell under the mouse takes Up / Down; no control in `ui_desktop` drags a value its own way.
