## Stage C1 (part 4): the screen is now run by a test, three interface bugs it found are fixed

- New `t8_uitest` (audit TEST-5). Before, no test ever drew the interface: the "UI tests" only searched the source for text. The new test draws real frames with no window, with the same code as the program. The whole screen moved from `main.cpp` into `src/ui_desktop/Shell.cpp` (`DrawShellFrame`) so the program and the test share it. After every frame the test renders one buffer of real audio.
- The tour: LIVE and TRACK, every tool (MIX LAB, CHORD LAB, MASTER FX), every track, NOTES / SOUND / MIX, the groove window, the help screen, an empty and a filled track, playing and stopped, at 1440x900, 800x520 and 2560x1440. Then the "monkey": random clicks, double clicks, right clicks, drags, the wheel, keys with and without Cmd / Shift / Option, and window resizes, for 500 frames per seed.
- It fails on a crash, on any ImGui assertion, on a scene change without the scene lock, and on NaN audio. ImGui assertions stay on in this test even in Release: unbalanced Begin/End or Push/Pop and ID clashes are caught. It also fails if fewer than one click in five lands on a control, so a test that clicks into nothing cannot pass.
- The test runs from `tools/run_tests.sh <build> uitest [--seeds N]`. HOME and the data folders point into the throw-away folder. PATH is emptied there, so "Reveal" or "Choose folder" cannot open anything. CI runs it on Linux (12 seeds), with ASan + UBSan (4 seeds) and on macOS (6 seeds).
- Fix (found by the test): the SIMPLE / COMPLEX / RHYTHM button of a melody part in RANDOM popped a colour it never pushed when the click switched it to RHYTHM. That could recolour the buttons after it for one frame.
- Fix (found by the test): WHOLE TRACK / THIS BRICK ONLY and THE KIT / OWN KIT in the SOUND view of TRACK changed the scene without the scene lock. So did THROW ONTO THE TRACK in CHORD LAB. The audio thread could read the scene while it was being changed.
