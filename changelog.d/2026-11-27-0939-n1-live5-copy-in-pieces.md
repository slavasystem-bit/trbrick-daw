## Stage N1 (LIVE-5, part 2): the Edited check no longer holds the sound for a whole project copy

Found with the XRUN hint of part 1 on the Mac: dropouts of about 3 ms every few seconds (CHORD LAB, a real project, 128-frame buffer = 2.9 ms), each one the screen holding the scene lock for 2.4-3.3 ms, named OTHER.

- **The "Edited" check (every 0.5-2 s) and the recovery copy (every 10 s) copy the project in short pieces** (`AppState::CopyProjectInPieces`): the head under one lock, then the scene slots 8 at a time, each under its own lock. Before, the whole project (81 scene slots) was copied in one hold, which grows with the project. The text and the hash are still made outside the lock. Only the screen thread changes a project's structure; the one thing the audio thread changes between pieces is mute / solo (NEXT BAR switches, for linked scenes in every scene of the group), so the last hold copies the mute and solo of all live scenes again and a saved file never holds half a group (review fix).
- `ProjectHead` (everything but the scene slots) + `struct Project : ProjectHead { PatternBank patterns; }`: the data and the file format are unchanged.
- **No more OTHER:** every scene lock of the app now has a name (`SceneLock`): the AppState functions (`DocHash`, `SaveSnapshot`, `TickTransport`, `SetMuteScene`, ...), the Sequencer functions the screen calls (`Sequencer::Play`, `Sequencer::LaunchScene`, ...), `ArmScope` and MIX LAB. The outermost name still wins, so a panel's name covers what it calls.
- 6 new `t8_selftest` checks: the piece-by-piece copy equals the project; the lock is free after it; a bar-line mute on linked scenes 4 + 13 landing between two pieces is in the copy for both; DocHash / SaveSnapshot never copy under one lock (source ratchet); no unnamed scene lock in the app and screen files (source ratchet).
- The `lock-5` check of #13 (a busy lock is given up) keeps its 5 ms limit but gets a loose wall-time bound: the macOS runner once descheduled the spinning thread for 32 ms.
